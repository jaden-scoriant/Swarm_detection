1. INTRODUCTION & DOCUMENT PURPOSE
================================================================================

This document provides the authoritative technical architecture, component 
design, mathematical formulations, data flow models, and operational 
specifications for the UAV Swarm Detection & Scene Analytics platform.

This specification serves as the comprehensive engineering blueprint for 
software engineers, machine learning operations (MLOps) personnel, computer 
vision specialists, and system evaluators responsible for deploying, verifying, 
maintaining, and extending the platform.

The system is structured with strict separation across the web server, model 
detector, analytics engine, and browser interface, ensuring testability, low 
latency GPU execution, and reliable offline operation.


================================================================================
2. PRODUCT SUMMARY & EXECUTIVE OVERVIEW
================================================================================

The UAV Swarm Detection application is a standalone, local analytical computer 
vision platform. It processes aerial imagery to detect multiple unmanned aerial 
vehicles (UAVs / drones), quantify swarm characteristics, evaluate spatial 
distribution, compute proximity clustering, classify swarm density, trigger 
configurable alert states, and produce human-readable scene characterizations.

Unlike standard object-detection demonstration scripts that simply overlay 
bounding boxes or dump raw JSON arrays, this application serves as an advanced 
analytical dashboard. It extracts structural spatial parameters from detection 
coordinates to provide instant, actionable aerial intelligence.

Target Operational Use Cases:
- Tactical and air-space perimeter surveillance monitoring.
- High-altitude aerial reconnaissance image analysis.
- Multi-UAV swarm density and formation assessment.
- Localized post-flight telemetry and sensor payload analysis.
- Offline technical evaluations and executive demonstrations.


================================================================================
3. DESIGN GOALS & CORE PRINCIPLES
================================================================================

The architecture is governed by the following engineering priorities:

- 100% Local & Air-Gapped Execution:
  Zero dependency on external networks, third-party APIs, cloud inference, or 
  remote model serving. All computations execute on the local workstation.

- Low-Latency GPU Acceleration:
  Leverage dedicated NVIDIA GPU hardware via CUDA and PyTorch for high-resolution 
  (1280x1280) inference with sub-second turnaround.

- Single-Load Model Memory Persistence:
  Initialize and load the trained neural network weights into GPU VRAM exactly 
  once on application startup, avoiding repetitive disk-to-VRAM transfer latency.

- Strict Tiered Separation of Concerns:
  Maintain a clear modular hierarchy: Flask Server -> UAVDetector -> Analytics 
  Engine -> Frontend Presentation.

- Zero Raw-JSON UI Discipline:
  The user interface must never present raw JSON dumps, debug trees, or Python 
  dictionaries. All internal metrics are transformed into structured visual 
  widgets, KPI cards, interactive canvases, progress scales, and sorted tables.

- Deterministic & Objective Scene Analysis:
  Generate structured, natural-language scene characterizations using deterministic 
  heuristic rule engines based strictly on spatial mathematics, avoiding external 
  LLM calls, non-deterministic hallucinations, or ungrounded threat inferences.


================================================================================
4. NON-GOALS & OPERATIONAL CONSTRAINTS
================================================================================

To maintain system integrity, strict boundaries are defined:

- No Cloud Services: No external cloud inference endpoints, AWS/GCP/Azure 
  dependencies, or remote database synchronization.
- No External LLMs: No OpenAI, Anthropic, or remote language model API calls.
- No Heavy Frontend Frameworks: No React, Angular, or complex Node.js build 
  pipelines. Standard HTML5, CSS3, and vanilla JavaScript ensure zero-build, 
  instant local serving.
- No Subjective Threat Inferences: The system evaluates spatial density and 
  numerical thresholds only. It does not infer hostile intent, weaponization, 
  or military combat status.

7.2 Module Separation of Concerns
---------------------------------
- config.py: Decouples runtime constants from application logic. Reads environment 
  variables with safe production fallbacks.
- detector.py: Strictly encapsulates the Ultralytics YOLO model. Knows only how 
  to load weights, infer on tensors, extract bounding boxes, and draw image overlays.
- analytics.py: Pure mathematical and statistical engine. Completely independent 
  of Flask and YOLO. Accepts raw bounding box arrays and returns structured metrics.
- utils.py: Provides system-level helpers (GPU name discovery, torch CUDA checking, 
  extension whitelisting, and file age cleanup).
- app.py: Lightweight orchestration layer. Handles HTTP routing, multipart 
  uploads, error trapping, background cleanup, and JSON response assembly.
- index.html & style.css: Provides modern layout, visual typography, and component cards.
- app.js: Consumes API payloads internally, calculates Canvas projections, updates 
  DOM nodes, and manages UI state transitions without displaying raw data.

9. CORE USER & SYSTEM FLOWS
================================================================================

9.1 Client-Side File Staging & Metadata Inspection Flow
-------------------------------------------------------
1. Operator navigates to `http://localhost:5000`.
2. Operator drags an image file over the upload zone or clicks "Choose Image".
3. `app.js` captures the `File` object and performs instant client-side validation:
   - Checks file extension against `['jpg', 'jpeg', 'png', 'webp']`.
   - Rejects unauthorized extensions with an immediate UI alert.
4. `FileReader` loads the binary stream locally into an `Image()` object.
5. The UI extracts:
   - Original filename
   - File size in megabytes (MB)
   - Native pixel dimensions (Width x Height)
6. The UI reveals the image preview thumbnail, displays the metadata, and enables 
   the "Analyze Image" action button.

9.2 Image Ingestion & GPU Detection Flow
----------------------------------------
1. Operator clicks "Analyze Image".
2. UI disables the analyze button, masks the dashboard, and displays the loading 
   animation ("Analyzing UAV Swarm... Running YOLO26s inference locally on GPU").
3. `FormData` payload containing the image is sent via `POST /api/detect`.
4. `app.py` triggers `purge_old_files()` to delete cached files older than 1 hour.
5. Server generates a cryptographically secure UUID (`uuid.uuid4()`).
6. Raw image is saved to `uploads/<UUID>_orig.<ext>`.
7. `UAVDetector.detect()` receives the image path and executes CUDA inference at 
   `imgsz=1280`, `conf=0.25` on GPU 0.
8. Detector extracts all bounding boxes into normalized dictionaries:
   `{x1, y1, x2, y2, width, height, center_x, center_y, confidence, class_id, class_name}`.
9. Detector invokes OpenCV to draw high-contrast, professional bounding boxes and 
   labels, saving the result to `static/outputs/<UUID>_annotated.<ext>`.

9.3 Post-Detection Spatial & Swarm Analytics Flow
-------------------------------------------------
1. `app.py` passes the detection list and image dimensions to `analytics.py`.
2. `calculate_analytics()` calculates:
   - Summary confidence values (average, min, max).
   - Swarm density category based on count boundaries.
   - Swarm alert status based on `SWARM_THRESHOLD` (Default: 10).
   - Detection footprint percentage relative to total frame area.
   - Spatial spread dimensions and standard deviations ($\sigma_x, \sigma_y$).
   - Nearest Neighbor Distance (NND) for spatial clustering analysis.
   - Natural-language deterministic scene analysis summary.
3. Server bundles metadata, detections, analytics, and image URLs into a JSON response.

9.4 Visual Hydration & Interactive Rendering Flow
-------------------------------------------------
1. `app.js` receives the JSON payload.
2. The loading mask is hidden, and the Result Dashboard is revealed.
3. Top KPI cards are hydrated:
   - Drone Count
   - Average Confidence (formatted as percentage)
   - Swarm Density
   - Alert Level (with color-coded badge: `none`, `normal`, `swarm-alert`)
4. Swarm Density Scale Widget updates by applying the `.active` class to the 
   matching tier (Sparse -> Moderate -> Dense -> Very Dense -> Highly Dense).
5. Secondary analytics cards populate with Min/Max confidence, Footprint %, 
   Average Bounding Box Size, Spatial Spread, and Nearest Neighbor Distance.
6. The HTML5 Canvas renders a 2D spatial coordinate map depicting drone centers, 
   the overall swarm bounding envelope, and the global swarm centroid.
7. The Scene Analysis text block displays the natural-language characterization.
8. The Detected UAVs table is populated with individual detections sorted by 
   confidence in descending order.

9.5 Annotated Image Export Flow
-------------------------------
1. The user inspects the annotated image preview on the left dashboard card.
2. The user clicks "Download Annotated Image".
3. The browser downloads the processed image artifact directly from the static 
   outputs directory.

9.6 System Health & Hardware Telemetry Flow
-------------------------------------------
1. On initial page load, `app.js` dispatches an asynchronous `GET /api/health` request.
2. Server queries PyTorch CUDA runtime:
   - GPU Availability
   - Hardware Name (e.g., "NVIDIA GeForce RTX 5060 Ti")
   - PyTorch Version & Device Identifier
   - Model Loading State & Configured Thresholds
3. UI updates the top status indicator with a green pulsing dot ("GPU Inference Online") 
   and populates the System Status metadata strip.

10.2 Tiered Layer Architecture & Boundary Isolation
----------------------------------------------------
1. Presentation Tier (Client Browser):
   - Vanilla JS + Bootstrap 5.
   - Strictly isolated from backend execution; communicates exclusively via JSON.
   - Enforces the "Zero Raw-JSON" policy by converting all responses into visual widgets.

2. Application / Routing Tier (Flask):
   - Handles HTTP protocol compliance, payload size restrictions, and endpoint security.
   - Coordinates file ingestion and cleanup without performing direct inference calculations.

3. Computer Vision / Inference Tier (detector.py):
   - Manages model lifecycle and GPU VRAM residency.
   - Transforms raw pixel buffers into normalized coordinate sets and generates 
     annotated image artifacts.

4. Analytical Reasoning Tier (analytics.py):
   - Operates as a stateless mathematical computation engine.
   - Transforms bounding box geometry into spatial intelligence and deterministic 
     natural-language narratives.

11. UAV DETECTION SUBSYSTEM ARCHITECTURE (detector.py)
================================================================================

11.1 Lifecycle & GPU Model Initialization Paradigm
--------------------------------------------------
To achieve optimal inference latency, the model follows a Single Initialization 
Pattern. When the Flask server starts, `app.py` instantiates the `UAVDetector` class.

- Model Path: `/mnt/ssd4tb/swarm_detection/runs/uavswarm_yolo26s_1280_100ep/weights/best.pt`
- Device Target: CUDA GPU 0 (`device='0'`)
- Resolution: `imgsz=1280`
- Confidence Floor: `conf=0.25`

The model weights are pinned in GPU VRAM across the entire server lifecycle. 
Individual HTTP requests never trigger disk reads or model reloading.

11.2 Inference Execution & Bounding Box Extraction
--------------------------------------------------
Upon invocation of `UAVDetector.detect(image_path, output_annotated_path)`:
1. The image is passed to `self.model(...)` with specified parameters.
2. The results tensor is parsed to extract bounding boxes in `xyxy` format:
   - $x_1, y_1$: Top-left coordinate (pixels)
   - $x_2, y_2$: Bottom-right coordinate (pixels)
   - $w = x_2 - x_1$: Box width
   - $h = y_2 - y_1$: Box height
   - $c_x = x_1 + \frac{w}{2}$: Centroid X coordinate
   - $c_y = y_1 + \frac{h}{2}$: Centroid Y coordinate
   - Confidence: Scaled float $[0.0, 1.0]$
   - Class ID & Class Name: Resolved from model dictionary (Class 0: "drone")
3. The extracted detections are sorted in descending order of confidence score.

11.3 Custom Analytical Image Annotation Engine
----------------------------------------------
Rather than relying on generic YOLO bounding box overlays, `detector.py` incorporates 
a custom OpenCV rendering engine:
- Palette: Technical Blue/Cyan (`BGR: (235, 140, 0)`), providing optimal contrast 
  against aerial terrains (vegetation, desert, urban, sky).
- Linework: 2-pixel precise rectangle borders around detected UAV targets.
- Tag Header: High-visibility label displaying sequence index and confidence 
  percentage (e.g., `#1 (98%)`).
- Top-Edge Clipping Protection: Automatic boundary adjustment ensures tags near 
  the top edge of the image frame ($y_1 \approx 0$) shift downward to prevent 
  visual clipping:
  `label_y = max(y1, text_h + 6)`

14. ANALYTICS ENGINE SUBSYSTEM ARCHITECTURE (analytics.py)
================================================================================

14.1 Metric Ingestion & Normalization
-------------------------------------
The analytics engine is encapsulated in `calculate_analytics(detections, img_w, img_h, swarm_threshold)`. 
It processes the raw detection array alongside native image dimensions, converting 
pixel coordinates into normalized spatial indicators.

14.2 Confidence Statistics & Distribution
-----------------------------------------
Given $N$ detections with confidence scores $C = \{c_1, c_2, \dots, c_N\}$ where $c_i \in [0, 1]$:
- Average Confidence: $\bar{C} = \frac{1}{N} \sum_{i=1}^{N} (c_i \times 100)$
- Minimum Confidence: $C_{\min} = \min(C) \times 100$
- Maximum Confidence: $C_{\max} = \max(C) \times 100$
(If $N=0$, all confidence metrics default to $0.0\%$).

14.3 Swarm Density Taxonomy & Categorization
--------------------------------------------
Swarm density is classified into six distinct operational tiers:

+------------------+-----------------------+-----------------------------------+
| Drone Count (N)  | Density Classification| Tactical Interpretation           |
+------------------+-----------------------+-----------------------------------+
| N = 0            | No Drones Detected    | Airspace Clear                    |
| 1 <= N <= 5      | Sparse                | Isolated Target Activity          |
| 6 <= N <= 10     | Moderate              | Small Group Formation             |
| 11 <= N <= 15    | Dense                 | Concentrated Swarm Configuration  |
| 16 <= N <= 20    | Very Dense            | Saturated Swarm Pattern           |
| N >= 21          | Highly Dense          | High-Density Multi-Target Swarm   |
+------------------+-----------------------+-----------------------------------+

14.4 Configurable Swarm Alert Heuristic
---------------------------------------
The alert heuristic evaluates multi-target presence against a configurable threshold 
(`SWARM_THRESHOLD`, default: 10):

  alert = "NONE"         if N = 0
  alert = "NORMAL"       if 1 <= N < SWARM_THRESHOLD
  alert = "SWARM ALERT"  if N >= SWARM_THRESHOLD

This provides immediate situational awareness without making unsupported tactical 
assumptions.

14.5 Estimated Detection Footprint (%) Formulation
--------------------------------------------------
Quantifies the percentage of the sensor frame occupied by detected bounding boxes:

$$\text{Footprint (\%)} = \left( \frac{\sum_{i=1}^{N} (w_i \times h_i)}{W_{\text{image}} \times H_{\text{image}}} \right) \times 100$$

Where $w_i, h_i$ are bounding box dimensions and $W_{\text{image}}, H_{\text{image}}$ 
represent total image resolution.

14.6 Bounding Box Spatial Geometry & Dimensional Statistics
-----------------------------------------------------------
- Mean Width: $\bar{w} = \frac{1}{N} \sum_{i=1}^{N} w_i$
- Mean Height: $\bar{h} = \frac{1}{N} \sum_{i=1}^{N} h_i$
- Smallest Bounding Box Area: $A_{\min} = \min_{i} (w_i \times h_i)$
- Largest Bounding Box Area: $A_{\max} = \max_{i} (w_i \times h_i)$

14.7 Global Centroid & Spatial Dispersion Bounding Envelope
-----------------------------------------------------------
- Swarm Centroid Coordinates:
  $$\bar{X} = \frac{1}{N} \sum_{i=1}^{N} c_{x,i}, \quad \bar{Y} = \frac{1}{N} \sum_{i=1}^{N} c_{y,i}$$

- Spatial Spread Bounding Dimensions:
  $$\text{Spread}_W = \max_{i}(x_{2,i}) - \min_{i}(x_{1,i})$$
  $$\text{Spread}_H = \max_{i}(y_{2,i}) - \min_{i}(y_{1,i})$$

- Standard Deviation of Drone Centers:
  $$\sigma_x = \sqrt{\frac{1}{N} \sum_{i=1}^{N} (c_{x,i} - \bar{X})^2}, \quad \sigma_y = \sqrt{\frac{1}{N} \sum_{i=1}^{N} (c_{y,i} - \bar{Y})^2}$$

14.8 Nearest Neighbor Distance (NND) Spatial Clustering
-------------------------------------------------------
To quantify spatial clustering, the engine calculates the average Euclidean distance 
from each drone centroid to its closest neighbor:

$$\text{NND}_i = \min_{j \neq i} \sqrt{(c_{x,i} - c_{x,j})^2 + (c_{y,i} - c_{y,j})^2}$$
$$\overline{\text{NND}} = \frac{1}{N} \sum_{i=1}^{N} \text{NND}_i \quad (\text{for } N > 1)$$

Low $\overline{\text{NND}}$ values indicate tightly clustered flight formations, 
while high values indicate dispersed flight paths.

14.9 Deterministic Scene Analysis Generator & Sector Mapping
------------------------------------------------------------
The system generates human-readable scene summaries using a deterministic rule engine:
1. Sector Location Partitioning:
   - X-Axis: Left ($c_x < \frac{W}{3}$), Center ($\frac{W}{3} \le c_x \le \frac{2W}{3}$), Right ($c_x > \frac{2W}{3}$)
   - Y-Axis: Upper ($c_y < \frac{H}{3}$), Central ($\frac{H}{3} \le c_y \le \frac{2H}{3}$), Lower ($c_y > \frac{2H}{3}$)
   - Composite Sector: e.g., "upper-center sector" or "central region".
2. Dispersion Factor:
   - Fractional Spread: $F_w = \frac{\text{Spread}_W}{W_{\text{image}}}, F_h = \frac{\text{Spread}_H}{H_{\text{image}}}$
   - Categorization:
     * $F_w > 0.6 \lor F_h > 0.6 \implies$ "widely distributed across the coordinate space"
     * $F_w < 0.25 \land F_h < 0.25 \implies$ "tightly clustered within the [Sector]"
     * Otherwise $\implies$ "moderately spread across the [Sector]"
3. Narrative Synthesis:
   Assembles the drone count, confidence average, density classification, alert status, 
   and spatial dispersion into a clean, objective paragraph without external LLM dependencies.

15.2 Visual Design System & Technical UI Language
-------------------------------------------------
- Background: Off-white canvas (`#f8fafc`) providing high contrast and reducing visual fatigue.
- Cards: Pure white containers (`#ffffff`) with subtle 1px slate borders (`#e2e8f0`) 
  and soft 4px elevation shadows.
- Typography: System sans-serif stack (`-apple-system`, `BlinkMacSystemFont`, `Segoe UI`, `Roboto`) 
  with strict uppercase metric headers and distinct visual hierarchy.
- Alert Badges: Restrained styling avoids aggressive full-screen flashes:
  * NONE: Subtle gray (`#f1f5f9`, border: `#cbd5e1`)
  * NORMAL: Soft emerald (`#ecfdf5`, border: `#a7f3d0`)
  * SWARM ALERT: Soft crimson (`#fff5f5`, border: `#fecaca`, text: `#9b1c1c`)

15.3 HTML5 Canvas Spatial Distribution Visualization Engine
------------------------------------------------------------
The spatial distribution map uses a native 2D HTML5 Canvas (`480x320` resolution) 
to project drone positions:
1. Coordinate Normalization:
   $$x_{\text{norm}} = \frac{c_{x,i}}{W_{\text{image}}}, \quad y_{\text{norm}} = \frac{c_{y,i}}{H_{\text{image}}}$$
   $$X_{\text{canvas}} = x_{\text{norm}} \times (W_{\text{canvas}} - 2 \cdot P) + P$$
   $$Y_{\text{canvas}} = y_{\text{norm}} \times (H_{\text{canvas}} - 2 \cdot P) + P$$
   (Where padding $P = 15\text{px}$).
2. Grid Rendering: A subtle $5 \times 5$ grid provides coordinate reference lines.
3. Swarm Region Envelope: A dashed teal bounding rectangle (`rgba(13, 148, 136, 0.25)`) 
   encloses the outer boundaries of the detection cluster.
4. Drone Target Pins: Solid blue dots (`#0284c7`) with outer rings and identification 
   indices (`#1`, `#2`, etc.) matching the table rows.
5. Global Centroid Crosshair: A high-visibility red crosshair (`#ef4444`) marking 
   the overall swarm center of mass.

15.4 Density Scale Progress Indicator Component
-----------------------------------------------
A five-segment horizontal scale visually represents density tiers:
`[Sparse] -> [Moderate] -> [Dense] -> [Very Dense] -> [Highly Dense]`
The active tier is dynamically highlighted with the accent color (`#0d9488`), 
providing instant contextual orientation.

15.5 Tabular Detection Inspector
--------------------------------
A responsive data table lists all positive detections sorted by confidence in 
descending order, providing:
- Detection Sequence (#)
- Confidence Percentage
- Center X (px) & Center Y (px)
- Box Width (px) & Box Height (px)

15.6 Client-Side Pre-Upload Probing & Validation
------------------------------------------------
Before dispatching network requests, `app.js` checks the selected file via 
`FileReader` to extract dimensions, size, and format, preventing unnecessary 
bandwidth and inference overhead for invalid files.

18. STORAGE LIFECYCLE & FILE SYSTEM MANAGEMENT
================================================================================

18.1 UUID Naming & Path Traversal Mitigation
--------------------------------------------
To prevent directory traversal attacks, filename collisions, and overwriting, all 
incoming uploads are renamed using randomly generated UUIDs:
- Raw Ingestion: `<UUID>_orig.<ext>`
- Annotated Artifact: `<UUID>_annotated.<ext>`

Original filenames are preserved solely in memory for UI presentation via 
`werkzeug.utils.secure_filename`.

18.2 Ingestion & Static Output Directories
------------------------------------------
- Ingestion Cache: `swarm_detection_app/uploads/`
- Static Output Cache: `swarm_detection_app/static/outputs/`

18.3 Rolling Expiration & Cache Purge Daemon
--------------------------------------------
To prevent disk exhaustion during continuous operations, `purge_old_files()` 
runs synchronously on each detection request:
- Expiration Threshold: Files older than 3600 seconds (1 hour) are deleted.
- Safety: Directory placeholders (`.gitkeep`) are strictly ignored.

19. HARDWARE ACCELERATION & CUDA RUNTIME ARCHITECTURE
================================================================================

19.1 Target Hardware Baseline
-----------------------------
- GPU: NVIDIA GeForce RTX 5060 Ti (~16 GB VRAM)
- Driver & CUDA: CUDA 13.0 (Driver >= 570.x)
- Host CPU: Intel Core i7-14700F (28 CPU Threads, ~31 GB RAM)
- Host Storage: High-speed NVMe/SSD storage (`/mnt/ssd4tb/`)

19.2 Memory Management & Single Initialization Pattern
------------------------------------------------------
The YOLO26s model allocates approximately 1.5 GB to 2.5 GB of VRAM during 1280x1280 
tensor operations. Retaining the model in VRAM across requests eliminates CUDA 
context initialization overhead, keeping per-frame latency under 50ms on modern GPUs.

19.3 Graceful CPU Fallback Mechanism
------------------------------------
If CUDA is unavailable or the GPU is absent, `utils.py` flags `cuda_available=False` 
and the system falls back to CPU execution (`device='cpu'`), ensuring continuous 
operation in non-GPU evaluation environments.
